# 突破策略雙時間級別搜尋（Stage 6–11，2026-09-20）

## 任務
找兩個不同時間級別、**樣本外正期望值**的突破策略。

## 結論：**沒找到 —— 兩個時間級別都無法證明樣本外正期望值**

並且本輪以**正面控制測試**確認了這個否定結論是可信的（管線對已知 edge 的偵測誤差 = 0）。

| 級別 | 開發期表現 | 樣本外表現 | 判定 |
|---|---|---|---|
| **4h** | IS 中位 Sharpe **+1.16**（100% 標的正） | TEST 中位 **+0.06**（57% 標的正，衰減到零） | ✗ 衰減 |
| **1h** | IS 中位 Sharpe +0.70（100% 正） | TEST 中位 **−2.35**（12% 標的正） | ✗ 崩掉 |

**額外驗證（Stage 13–14）**：組合 Sharpe +1.31 看似不錯，但——
- 贏不過「同交易數隨機進場」的 null（p=0.080）
- 多腿與買進持有相關 **+0.87** → 是市場 beta，不是 alpha

## 本輪最重要的新發現：**出場方法是關鍵維度**

前幾輪（`research/breakout_jev/` 十階段 + `breakout_jev2` Stage 1–5）**只測過固定 ATR 停損/停利（OCO）一種出場**。
那是趨勢跟隨的結構性錯誤 —— 固定停利把大趨勢砍在半路，而趨勢跟隨的獲利本來就來自少數極端獲利單。

改成 **唐奇安出場**（收盤跌破前 N 根最低）或 **移動停損** 後，4h 突破的樣本內表現**戲劇性改變**：

| 出場方法 | 4h IS 中位 Sharpe | 4h IS 平均每筆 |
|---|---|---|
| OCO（舊做法） | 約 0.0 | 約 −0.25% |
| **唐奇安（96，both）** | **+1.16** | **+9.65%** |
| 移動停損（192） | +0.90 | +0.67% |

**但樣本外全部失效。** 這是「找到了正確的機制，但它沒有可持續的 alpha」——兩件事不矛盾。

有經濟意義，但**無法事先判斷**哪一年是哪一種 → 不能交易。

## 嘗試過的 regime 過濾器（Stage 9）——也失敗

只在前段開發、留出段只測一次：

| 策略 | 開發期 | 留出期 |
|---|---|---|
| 4h + EMA200 趨勢過濾 | 中位 Sharpe +0.87（**100% 標的正**） | 中位 **+0.18**（57% 正） |
| 4h + 波動率百分位過濾 | +0.81（100% 正） | 未通過候選篩選 |

**開發期 100% 標的為正、留出期全崩 = 過擬合的標準長相。**

## 誠實檢定：Stage 10 的那個「顯著」是假象（Stage 11）

Stage 10 用 182 個 okx 標的做橫斷面 bootstrap，得到唯一存活候選：

```
trail_both_lb192:  留出平均 +0.5556%  正標的 58%  bootstrap p=0.0254  → 看起來顯著
```

**三項修正檢定把它證偽：**

| 檢定 | 結果 | 判定 |
|---|---|---|
| A 時間分塊一致性（4 段） | 4/4 段為正 | 通過 |
| B 標的集中度 | 前 10 檔貢獻 **61%** 獲利 | ✗ 不是普遍 edge |
| C 相關性修正 | ρ=0.077 → 名目 182 檔的**有效獨立樣本僅 12.2** | ✗ |

**關鍵計算：**

```
名目 t=2.06   p=0.0203        ← 表面顯著
修正 t=0.53   p_eff=0.3022    ← 真實
Bonferroni 門檻（5 配置）= 0.0100 → 不通過
```

**教訓（最重要的方法論收穫）**：
> 標的間平均相關只有 ρ=0.077 看起來微不足道，但 `n_eff = N/(1+(N−1)ρ)` 下，
> 182 檔只剩 12.2 個獨立樣本。**用橫斷面標的數當樣本量做 bootstrap，在相關性資產上會系統性高估顯著性。**

這是 Stage 10 差點給出假正面結論的原因。若沒做 Stage 11，就會交付一個不存在的 edge。

## 正面控制測試（Stage 13–14）：驗證管線本身可信

**為什麼要做**：一路得到「沒有 edge」，但若管線本身無法偵測 edge（成本設錯、分割錯誤、指標有未來函數），所有結論都不可信。標準做法是先餵「已知有 edge」的東西進同一條管線。

### 結果：管線正確，Edge 不存在

**B. 合成 edge 注入（決定性）**

| 注入 μ | 注入 σ | 理論 Sharpe | metrics 回報 | 差異 |
|---|---|---|---|---|
| 0.004 | 0.02 | 8.1030 | 8.1030 | **0.00e+00** |
| 0.002 | 0.02 | 3.4588 | 3.4588 | **0.00e+00** |
| 0.000 | 0.02 | −1.1853 | −1.1853 | **0.00e+00** |
| −0.002 | 0.02 | −5.8295 | −5.8295 | **0.00e+00** |

→ **管線對已知 edge 的偵測完全精確，Stage 6–12 的失敗結論可信。**

**C. 訊號置換檢定（正確的零假設）**
null = 從全期隨機挑「相同交易數」的棒強制觸發（同方向、同出場規則）。

```
組合 Sharpe +1.31   vs   null P95 +1.52    p=0.080   不顯著
組合平均    +1.59%  vs   null P95 +2.83%   p=0.170   不顯著
符號檢定    4/7 檔高於 null 中位數          p=0.500   不顯著
```

**D. 多空分解（最關鍵）**

```
多腿組合平均 +4.19%    空腿組合平均 −0.32%
corr(多腿平均, 買進持有) = +0.87
```

→ **「高於隨機進場」完全是市場 beta，不是 alpha。** 多腿只是買進持有的代理。測試期間市場平均 −5.4%，但 XRP +139.9% 這類極端值主導了多腿 —— 選到贏家的運氣，不是訊號。

### 本階段抓到的四個方法論陷阱（都會產出假正面結論）

1. **置換「交易順序」是無效檢定** — `Sharpe = mean/std×sqrt(n)` 是**順序不變量**，
   洗牌後 sd=0.000000。正確做法是置換**訊號位置**。
2. **null 必須強制觸發訊號** — 只把其他棒關掉，隨機挑中的棒仍帶真實通道值 →
   幾乎零交易 → null 分布全空。必須讓被挑中的棒強制符合突破條件。
3. **合成測試的理論值必須用與 metrics 相同算法** — 我用多乘 `sqrt(2190/24)` 的理論值
   對比，誤判「管線有偏差」。改用相同算法後誤差 = 0。
4. **多空系統必做多空分解** — 若不做，會把市場 beta 當成 alpha。
   `corr(多腿, 買進持有) = +0.87` 是決定性證據。

## Stage 15–17：市場廣度濾網 + 切點敏感度（最後一擊，也失敗）

**動機**：Stage 8 證明 4h 突破的失敗是 regime 依賴，但先前用的濾網（個股 EMA200、ATR 百分位）都是**個體**指標。廣度是**市場層級**指標，資訊可能不同。

**結果 1：廣度沒有額外資訊**
```
breadth>=0.5 : 中位Sharpe +0.91   vs   mktmom_top50 : +0.93   差異 −0.01
corr(breadth, 市場動能) = +0.82
```
→ 廣度與市場動能**完全等價**，只是同一個東西的不同寫法。（我事先標記了這個 red flag 並設計了並排比較，確認成立。）

**結果 2：切點敏感度摧毀了唯一的正面訊號**

Stage 15 的 `none`（無濾網）看似「開發 +1.04 → 留出 +0.30，71% 標的正」，
與 Stage 7 的 TEST +0.06 不一致 → 追查（Stage 16）發現**只差在留出期起點**：

| 切法 | 留出起點 | 中位 Sharpe |
|---|---|---|
| 各檔全長 75% | 2024-06-11 | +0.06 |
| 共同軸 75% | 2024-09-13 | +0.21 |
| 共同軸 60% | 2023-07-29 | +0.30 |

完整掃描（Stage 17，切點 50%→90%）：

```
中位 Sharpe 範圍 [−0.24, +0.34]   標準差 0.17
正標的比率   範圍 [29%, 71%]
同時通過「Sharpe>0.3 且 正標的>=60%」的切點: 1/9
```

→ **不穩健**。同一策略、同參數、同資料，只改切點就跨越零。
Stage 15 的正結果是**切點運氣**，不是可交易 edge。

### 這個階段最重要的方法論教訓

**留出期切點本身就是一個可優化的參數**。若只跑一次，很容易剛好選到有利的切點。
必須做**切點敏感度掃描**（sweep），並要求多數切點都通過，才算穩健。

Stage 6–17 全程只用了一種切點（Stage 7 用 75%、Stage 15 用 60%），
若沒做 Stage 16–17 的追查，就會把切點運氣當成 edge 交付。
