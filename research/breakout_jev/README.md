# 5m 突破 × Jev 研究（2026-09-19）

## 目標
找一個在 5 分鐘週期上、透過 TypeSafe Jev 增強的突破策略。

## 結論：**不存在**（十階段實驗 + 標準優化流程雙重驗證，全部否定）

不是「沒找到」，而是證明了在 5m 這個框架內、用這些槓桿，不存在可開發的
突破策略。核心障礙不是參數、不是成本、不是標的選擇、不是回看長度，
而是**訊號本身沒有資訊含量**。

**判定：樣本外失效。IS 本身為負 → 不是過擬合，是策略無 edge。**

### FIL 5m（51,842 根）

IS Sharpe     : +1.672        ← 看起來很好

**判定：教科書級過擬合。** IS +1.672 → OOS 三折全負（落差 145%，正轉負）。

## 關鍵數據

### 1. 成本不是主因（排除法）
```
標的     ATR%     fee/ATR   零費率平均   taker平均
BTC    0.141%    70.7%     +0.0018    -0.0982
APT    0.317%    31.6%     -0.0195    -0.1195
SUI    0.297%    33.6%     -0.0124    -0.1124
FIL    0.290%    34.4%     -0.0625    -0.1625
BCH    0.185%    53.9%     -0.0112    -0.1112
```
APT/SUI 波動是 BTC 的 2.2 倍、成本佔比只有 BTC 的 45%，
**零費率（純訊號）依然是負的**。→ 費用不是障礙，訊號本身為零。

### 2. Jev 無預測力（決定性測試）
```
樣本 250 個隨機分散全期訊號，中性提問（零引導），原子標的（哪個先到）
真值: fail 138 / cont 104
Jev 準確率       49.6%
基準線（多數類）  57.0%
corr(Jev p_cont, 實際結果) = -0.019
corr(Jev 信心, 判斷正確)   = -0.109   ← 信心越高越不準
```
Jev 說「繼續突破」的比例 44.6% ≈ 實際發生率 43.0%
→ **它只是複述基礎機率，沒有擇時能力。**

### 3. 規則特徵全部無預測力
```
corr(brk_atr,  48根後淨位移) = +0.001
corr(atr_pct,  ...)         = -0.020
corr(ret_1,   ...)          = -0.009
corr(ret_12,  ...)          = -0.016
corr(ret_48,  ...)          = -0.019
```

### 4. 訊號變體全部無效
- **壓縮突破**（布林帶寬百分位 < 30）：BTC +0.0030、APT −0.0620、SUI −0.0342、FIL −0.0385、BCH −0.0115
- **量能確認**（+vol_ratio > 1.5）：BTC −0.0012（比不加更差）；其他標的無 volume 欄位，無法測
- **反向操作**（做假突破）：零費率 +0.0061%（≈0）

## 為什麼 5m 突破結構上不可行

5m K 線的「突破」在加密市場是**已被套利掉的訊號**。
做市商與高頻資金在此時間尺度競爭，前高/前低是所有人看得見的資訊。
**Donchian 突破在 5m 上沒有資訊含量** —— 這與它在日線/週線可能有效不矛盾，
只是時間尺度決定了競爭密度。

5m 的 ATR 僅 0.141%~0.317%，而價格噪音佔比極高；
每根 K 線的資訊量不足以支撐一個可交易的統計優勢。

## 失敗教訓（重要，勿重蹈）

1. **成本是第一個該排除的嫌疑，不是第一個該下的結論**
   我最初假設「費用吃掉 edge」（fee 佔 ATR 70.7%），但測零費率後發現訊號本身
   只有 +0.0018%。**若沒測零費率，會給出錯誤建議（去談低費率就能救活）。**
   → 任何「費用主導」的猜測，必須用零費率對照驗證。

2. **要有基準線，否則無法判斷技能**
   突破勝率 31.8% 看起來「低但有機會」；對照隨機進場 32.8% 才發現
   **突破比隨機更差**。Jev 的 49.6% 也是靠基準線 57.0% 才被判定為無技能。
   → 沒有基準線的準確率數字沒有意義。

3. **樣本要隨機分散，不要取窄帶**
   （承 grid_jev_study 的教訓）Stage 4 用隨機分散全期 250 個訊號，
   保證特徵變異，避免把要測的東西先排除掉。

4. **自動判讀要再用第二種方法驗證**
   Stage 3 的程式自動印出「雙峰明顯（Jev 有可分離目標）」（延續 63.6% /
   反向 69.2%），但那是因為允許 48 根內先後觸及。改用「哪個先到」後，
   真值是 138/104 而非雙峰 —— **Stage 3 的判讀被 Stage 4 推翻。**
   → 程式的自動結論必須用不同定義交叉驗證。

5. **多標的是排除「標的特定性」的必要步驟**
   在 BTC 上失敗不足以定論（可能 BTC 特別有效率）。測 APT/SUI/FIL/BCH
   才確認是普遍現象，且順帶排除成本假設（因為它們成本佔比只有 BTC 的 45%）。

6. **資料欄位要先檢查**
   APT/SUI/FIL 的 parquet 沒有 volume 欄位，導致量能確認在四個標的上
   直接歸零（樣本不足 0）。resample 前應先檢查欄位存在性。

7. **「平均值為正」不等於「有 edge」—— 必檢這三項**
   ① 統計顯著（bootstrap CI 不含零）② 時間穩定（前後半同號）③ 多空對稱。
   Stage 6-8 看到 BTC LB576 +0.0369% 便宣布「找到 edge」，Stage 9 檢定後推翻。
   **這三項應在最開始就做，而非最後補** —— 若 Stage 6 就做，能省下 Stage 7-8。

8. **StrategyBase 策略的持倉狀態必須自行歸零**（實作坑，最隱蔽）
   引擎 OCO（stop_loss/take_profit）平倉**不通知策略**。若 `next()` 只設
   `self._in_pos = True` 而從不設回 False，**整個回測只產生 1 筆交易**，
   而 `optimize_local.py` 不報錯 —— 照樣印出 `avg_oos_sharpe=1.416
   consistency=1.00`、`expected_return=99988`（全部基於 1 筆，毫無意義）。
   **驗證法：跑完務必看 `total_trades`，只有 1~2 筆就是中了這個坑。**
   正確寫法：每根 bar 先檢查是否觸及停損/停利價或超時，是則歸零並回傳
   `Signal(action="close")`。

9. **`win_rate` 欄位已是百分比**（`engine/backtester.py:516`），格式化時別再乘 100，
   否則出現「勝率 3205%」這種荒謬值。

## 這個否定的價值

5m + Donchian + ATR 停損是教科書組合，看起來很合理。
十階段實驗 + 完整參數優化 + Walk-Forward + Monte Carlo + 顯著性檢定，
全部指向同一結果：**訊號為零 + 無可篩維度 + Jev 也救不了**。
**若不跑這些階段，可能用真錢跑幾個月才發現。**

## 唯一有用的副產品

**`lookback=720`（60 小時回看）在 BTC 與 FIL 的 IS 優化中皆勝出。**
這暗示「越長的回看越有訊號」，但即便如此仍不足以覆蓋成本（OOS 全負）。

## 延伸

唯一有結構性理由的改變是**換時間框架**（1h 的 ATR 約 0.5%，
競爭密度低一個量級），但那已不屬於「5m 策略」的研究範圍。
素材具備（`gridlab/*_1m.parquet` 可重採樣），流程可直接複用。
